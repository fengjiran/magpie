## 实现

- 新增公开 C++20 `ThreadPool` API、`Task`/`TaskImpl`、按存储对象 `F&` 调用的 callable 约束、`submit_async` 和带 `QueueFull`/`ShuttingDown` reason 的导出异常。生产目标保持无第三方运行时依赖。
- 实现固定 worker 组和预分配槽位的全局有界 mutex ring。M1 只用全局 FIFO 队列；`local_deque_capacity` 会校验并向上取整，但在后续 deque 里程碑前不参与调度。
- 实现 CallerRuns、Abort、DiscardOldest、broken promise、提交 Gate、先计数 pending、统一归零通知、quiescent stats 和 worker/inline completion 分项。全队时 worker 子提交始终 inline，以保证单队列基线不会让 worker 按 Abort/Discard 策略丢失子任务。
- 实现独立 owner TLS 与可嵌套 ExecutionFrame；同步 `shutdown`/`drain` 的 guard 覆盖任务、异常 handler、CallerRuns、被丢弃 task 及 capture 析构。池拥有的 exception handler 在 `ExecutionScope` 内复制和清理，并在其他 Impl 状态仍存活时销毁。handler 可并发调用，用户负责保护其可变状态。
- 实现分阶段构造、部分 worker 创建失败时停止、唤醒并 join 后重抛原异常；macOS generic backend 使用 `std::thread`。Linux `pthread_create` trampoline、stack attributes 和 allowed logical CPU 轮转亲和性已编写，但本机不能编译或执行该分支。亲和性在线程创建成功后 best-effort 设置，失败只 warning 并保持不绑核，不会让 cpuset 变化导致构造失败。generic backend 会 warning 并忽略 stack/affinity；Linux stack attr 失败会 warning 并退默认。
- M1 的等待器使用 `std::condition_variable`。stop 谓词在 queue mutex 下发布；worker 仅在 stopping、提交 Gate 为零、pending 为零时退出。stop 发布、关闭期 Gate 1→0 和 pending 1→0 会配对广播；常态 gate/pending 归零不广播，任务发布只 notify_one。该机制允许关闭期停车，不是 M5 EventCount 注册协议。`wakes` 统计 CV notify 调用数，`wake_threads` 保持空。
- M1 的 DiscardOldest 在一个 queue mutex 临界区删除当前可取得的全局队头并接收新任务；新任务先发布并通知，旧 Task 解锁后销毁，capture destructor 不在队列锁内运行。它没有 MPMC 的 reservation retry 窗口，切换 MPMC 时必须重新实现相同的外部语义。
- 确定性交错 hook 只编译进单独的 `magpie_test_support` 静态库。Release 生产 archive 的 `nm -gU` 输出没有 hook setter；该 setter 只出现在 test-support archive。`BUILD_TESTING=ON, MAGPIE_ENABLE_TEST_HOOKS=OFF` 的构建也通过。
