## 交付与协议

- `ChaseLevDeque`：有界Task*槽、owner push/pop、单元素steal；完整release发布、双侧SC fence、成功/失败SC CAS；最后项失败恢复稳定`b+1`；失败候选不解引用，不执行或销毁Task。
- signed 64-bit索引不重置/回绕，配置与真实原子槽byte size检查；空pop的0→−1是合法中间态，上限fail-fast在Release仍生效。
- 所有WorkerCtx/deque/victim列表先构造，再启动线程；每worker预分配64项接收buffer和随机victim permutation。owner TLS同时检查池实例，跨池提交走目标全局队列。
- 本地满只把当前incoming转投全局一次；全局不可取得槽则worker CallerRuns，外部Abort/DiscardOldest不改变内部完成义务。没有旧半批spill或overflow缓冲。
- local pop→全局bulk≤min(32,capacity)→随机victim重复单元素steal≤min(64,capacity)。完整转移后才执行用户代码；失败后持CV mutex复查并完整探测所有其他victims，再wait或退出。
- 本地发布和批迁移补通知，发布先于持CV mutex通知；保留M3提交门/pending/drain/关闭握手，未接入WaitSlot/epoch/futex。
- `MAGPIE_ENABLE_WORK_STEALING=ON`须配MPMC，默认OFF；四个`*-workstealing` presets；新增只读`scheduling_backend()`，`BuildInfo`布局不变。独立静态/共享consumer传递相同构建选项。
- `stolen`计成功单项窃取，重复迁移可多次计；`local_spills`计本地满后的转投尝试。worker/inline完成与pending守恒保持。
- harness新增固定子项批的worker scaling/skew和真实local/total slot口径；旧binary CLI/replay保持可用。说明见 [工作窃取](../work-stealing.md)、[benchmark](../benchmarks.md)、[ADR-001](../../design/chase-lev-deque-adr.md)。

先测65536子项/同容量local的组仍保留：global W4 inline median约93.03%，worker与total约219183/3096639 ops/s，不能用于队列获取路径scaling对照。按照benchmark计划把批规模缩至global4096以内，以相同local4096补测以上4组，inline全部0；没有删除旧组或把重跑伪装成初始结果。原大批M4 T4/T1约1.396，hotspot却比uniform快约25%，与4096批结果不同，说明fixture/batch粒度不能混算。

1. **是否有明确收益？** 同树M4/global median ratio1.058，4096 uniform1.013；M4的IQR分别约17.7%/47%，不足以宣称稳定提升。相对原frozen mutex空任务ratio0.871，是M3+M4组合路径对基线的开发回归点，不是只隔离deque成本的结论。
2. **成本转移在哪里？** 新增本地原子槽、SC pop/steal fence、逐项CAS、迁移和每worker victim存储/扫描。每次本地发布仍持通知mutex；gate/pending/submitted与Task分配未消失。4096 hotspot成功stolen median13652098次，对约610万完成项约2.2次迁移/项；uniform stolen约2739085次。迁移次数与执行次数不同，这些机制可能造成额外cache/通知成本；没有硬件采样，不作精确RMW耗时或加性归因。
3. **尾延迟怎样？** 空任务的frozen/M4 p99桶上界median523.299/273.842us，拒绝median152/102；饱和队列/批接收与buffer footprint同时改变，24.1%宽桶也不能关闭5%正式门槛。新local-batch fixture不采集latency，输出NA，完整开放到达率p99矩阵仍待正式平台。
4. **扩展性与fallback？** 匹配4096批M4 T4/T1约1.709，尚未长窗口测worker2/8；inline0只消除了这组fallback混合，并不证明线性扩展。大批global的93% inline组已明确排除scaling判据。local每worker4096+global4096在W4共20480槽，对照global只有4096槽；已报告buffer差异，未用总buffer相等来证明性能。
5. **偏斜与allocation？** 4096 hotspot相对uniform的worker leaf损失约55.33%，高于设计20%目标，当前代表点不达标。原大批相反趋势说明不能挑负载宣称通过。same/cross受控路径含不同同步/销毁资源，不相减得出纯allocator耗时；Task每项分配仍是现实成本。

## 已保留失败与未关闭门禁

首轮R2 fixture错误地让owner先降低bottom，再启动thief探测，thief自然不能读到可领取边界，预期“thief赢CAS”不成立。失败 `first-review-20261003/LastTest.log` 保留；修正为先暂停thief候选、再暂停owner候选，释放thief赢CAS/销毁，再释放owner，真正覆盖CAS失败后的恢复与过期候选。后续验证用新目录，不覆盖失败。

Linux CI新增MPMC+stealing的Release/ASan GCC与Clang Release/TSan条目，未远端执行。GCC官方将atomic_thread_fence列为TSan不支持特性，因此TSan CI选Clang，保留真实fence和-Werror，未屏蔽诊断；详情见 [平台矩阵](../platform-matrix.md)。本机/usr/bin/g++实际也是AppleClang，不能冒充GCC证据。

M0–M3原有Linux/物理机门禁未由本轮关闭；Linux native/ARM64仍无资源证据，完整线程stack dump仍待平台实现。M5 EventCount/futex/spin-yield未开始，现有CV测试不是其验收。正式性能及默认替换需要固定物理Linux完整资源/负载矩阵，不从单个开发代表点推导默认更改。没有commit、push或发布。
