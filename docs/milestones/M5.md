## 实现与审核修复

每 worker 稳定分配 WaitSlot；64位 epoch 不回绕，word 为 Idle/Waiting/Signaled。通知无条件先推进 epoch，再扫描/CAS/wake。generic 使用每槽 mutex/cv，Linux使用 PRIVATE futex、四字节/对齐/lock-free ABI 检查和 EAGAIN/EINTR 分类；其他 syscall 错误 fail-fast。

池采用 local/global/随机 victim → 64 次 cpu_relax → 8 次 yield → prepare/enter → 再查 stopping → 完整 victim 扫描 → epoch 复查 → backend wait/leave。注销前不执行用户代码或迁移通知。停止以后不重新停车，pending/gate 未归零时继续探测；长任务期间可产生忙等 CPU 成本。

审核反例：只有一个已接受任务，shutdown 后两个 worker 交替将它整批重新发布，各迁移101次而执行数仍0、pending仍1。修复后的非空批次保留 batch[0] 为当前 worker 的独占执行项，只逆序发布剩余指针。成功取得非空批次必返回该保留项，其他 thief 无法再次夺走；剩余项发布后通知，单项批次没有重新发布。global/victim 接收容量仍按 local_capacity 钳制，队列原语、内存序和 pending 退休规则不变。

这提供任务级推进：在已认领线程继续调度、用户任务最终返回的前提下，每次非空批领取至少有一项走向执行；不把“成功迁移一次”当作执行进展。保留项仍在注销及队列操作结束后执行，不引入 helping wait 或队列内用户回调。

配置、统计及 Linux 验收入口见 [EventCount 说明](../event-count.md)，协议见 [ADR-002](../../design/event-count-adr.md)。主设计、ADR-001、测试计划、平台与 benchmark 文档已同步。

## 本轮 correctness 证据

平台：macOS x86_64 / AppleClang17 / generic EventCount。全部自有目标保留 warnings-as-errors，Release 最终 `-O2`。四个独立目录 `build/m5-fix-{release,tsan,asan,cv}` 显式配置 MPMC/work-stealing；前三者启用 eventcount/generic，cv 为同源码 control。

| 配置 | fast suites | stress suites |
|---|---:|---:|
| Release EventCount | 20/20 | 3/3 |
| TSan EventCount | 16/16（不构建death） | 3/3 |
| ASan+UBSan EventCount | 20/20 | 3/3 |
| Release CV control | 19/19 | 3/3 |

每配置执行 configure、`cmake --build ... --parallel 2`、`python3 scripts/run_ctest.py --build-dir ... --mode fast` 和 `--mode stress`。实际参数、退出码与输出在归档各配置目录的 command.json/stdout/stderr。包含 static/shared 独立消费者、此前 async 契约、原语与池百万ID守恒、EventCount 注册/关闭及部分构造失败回归。

新增三个正式池级回归：

- `GlobalBatchKeepsExecutionClaimDuringShutdown`：全局单项领取后暂停执行者，关闭后让另一 worker 完成窃取探测，执行项不能被重新认领。
- `StolenBatchKeepsExecutionClaimDuringShutdown`：从 victim 领取单项后重复同一条件，原 owner 恢复后也不能夺回执行项。
- `BatchRemainderWakesParkedWorker`：全局16项已被领取但未发布时确认另一 worker 到达最后等待边界；发布剩余15项后，在领取者的保留项被外部 latch 占用期间，要求其余15项完成。

新回归使用既有测试缝和10s watchdog，不以睡眠猜测交错。临时变异验证：恢复整批再发布使两项执行权回归明确失败（exit 1）；删除剩余项通知使对应回归输出 leaves=0 并由 watchdog 退出124。源/命令/输出在 `mutants/`，变异不进入生产源码。

开发首版新测试错误地阻塞了 victim 的首次窃取，watchdog 输出 owner=2 并退出124；`focused.*` 日志保留。修正测试同步后使用新日志 `focused-v2.*`，三项通过；没有把第一次失败覆盖为成功。主设计骨架检查通过，只作为文档一致性辅助。

## Linux 原生门禁验收（2026-10-11）

2026-10-11 用户提供 WSL2 Linux 环境并明确裁定：WSL2（真实 Linux 内核、原生 futex syscall）可作为 M5 正确性门禁的「Linux 原生」证据；该裁定不扩展到 M6 性能验收（M6 仍要求固定物理 Linux，按平台矩阵与 AGENTS 规范 WSL 不替代）。

环境：Linux 6.18.40.1-microsoft-standard-WSL2、x86_64、20 vCPU；GCC 14.2.0（Ubuntu 24.04）、Clang 18（用户执行 `sudo apt install clang-18`）、CMake 3.28.3、Python 3.12.3、Unix Makefiles（无 ninja）；GTest 经 FetchContent 固定 v1.14.0。源码 `98e8259d`，工作区 clean。构建目录 `build/{release,tsan,asan-ubsan}-eventcount` 与 `build/release-eventcount-generic`；命令、输出、环境与 CMakeCache 摘录在 `results/linux-m5-20261011/`（本机归档）。

| 配置 | fast | stress |
|---|---:|---:|
| GCC Release、MPMC+workstealing、eventcount auto=futex | 19/19 | 3/3 |
| GCC ASan+UBSan、同上 futex | 19/19 | 3/3 |

fast 中包含同一原语的 generic 与 futex 两套语义用例、Linux 专属真实 syscall 窗口（`RealSignalInterruptsKernelWait` 的 EINTR 分类、`SpuriousWakeWithoutWordChange` 的 spurious 注销、`WakeBeforeKernelWait` futex 分支的 EAGAIN 与 `wait_syscalls` 计数）以及池级关闭/迁移回归；`registered==0` 断言覆盖 join 后注册归零。四字节 ABI/对齐/lock-free 检查为编译期断言，随构建通过。

退出门禁逐条：Linux 与 generic 语义测试均通过（含 control 变体对照）；Linux 真实窗口与本次结果已归档；停止后的晚注册不睡过最终通知（池级 `ShutdownBeforeRegistration`/`ShutdownAfterRegisteredCheck`/`ShutdownAfterEpochRecheck` 通过）；全部 join 后注册数归零（`registered==0` 断言）；统计区分 syscall 调用/返回与 backend 探测（`wait_syscalls`/`wait_returns`/`eintr`/`wakes` 断言）。模型证据口径不变：GenMC 抽象模型在 macOS 归档，模型不随 futex 后端改变而重跑（无源码变更，见 `model-reuse.json`）。

五问与接受决定：

1. **路径与收益：**空任务代表点吞吐ratio约1.619，IQR分别约5.6%/4.4%。EventCount减少成功发布必取全局停车mutex的路径，并引入epoch/注册扫描及退避；数据属于这一组合机制，不是独立原语耗时。只支持本机该代表点，不宣称futex或所有负载更快。
2. **成本转移：**gate/pending/submitted与Task分配仍存在；每次通知仍有epoch SC RMW，有注册者才扫描并可能取得generic槽mutex。新增独立WaitSlot和统计成本。CV的wakes是notify请求，EventCount是成功标记后的backend调用，不能直接相减当作减少的内核wake数量；generic的真实syscall/wake_threads不可用。未作硬件采样，不作加性分解。
3. **尾延迟：**空任务p99桶上界ratio约1.911，同时供给/处理速度和拒绝分布改变（CV拒绝median0，EventCount59），不能只按吞吐判断接受。稀疏发布吞吐由1000/s输入限制，不构成加速；两组p99同桶也不证明5%内等价，桶宽约24.1%。稀疏process CPU约增加27.9%。保留CV默认。
4. **扩展性与关闭：**只覆盖W1饱和和W4稀疏/空载/关停，没有重新跑worker scaling/skew完整矩阵。空载都接近测量底噪，不用其比值宣称稳定差异。EventCount关停drain CPU较高且IQR明显；drain CPU减task CPU约0.0214s，仍包含调度/同步等成本，不能全归为纯忙等或直接关闭W2.8触发判断。
5. **适用范围与后续：**所有测量为macOS/generic、unbound CPU，buffer与采样在每对中一致（local=16；global常规4096、关停16384）。尚无物理Linux、NUMA/硬件采样、真实futex或完整到达率矩阵。候选保留用于开发，M6标定和默认替换仍须独立验收，不改变门槛或隐藏尾延迟/CPU代价。
