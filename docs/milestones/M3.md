- 日期：2026-10-03（Asia/Shanghai）。
- 状态：**原语和池候选已实现，本机 correctness/model 验证通过，代表点开发性能对照已归档；默认保留 mutex，正式 Linux/性能门禁未关闭。**

## 交付与协议

- `MPMCQueue<T>` 的 slot/position 协议、类型约束、容量/实际 byte size、64位/Release 上限 guard、单项 bulk、weak unavailable。
- `MAGPIE_QUEUE_BACKEND=mutex|mpmc`，默认 mutex；四个 `*-mpmc` presets。静态/共享独立 consumer 传递相同 backend，`BuildInfo` 布局不变，新增只读诊断函数。
- MPMC 池常态 dequeue 不持停车 mutex，失败后持锁复查；发布后持同一 mutex 通知，保持 CV 探测→wait 和关闭握手。通知 mutex、gate/pending/submitted/alloc 成本仍存在。
- DiscardOldest 只认领当前头，不跳过 unpublished head，按主设计限额2次；旧 Task 解锁后销毁，再 dec_pending，重试新项；最终失败销毁 incoming 并回退，只计一次 rejected。
- 所有权成功发布后只覆盖托管字段为空，不再读取可能已被 consumer 删除的 Task*。失败 try 不转移所有权。
- 原语/真实池确定性交错、position→id 历史配对、两个百万 ID stress、Release/ASan death、独立 watchdog 与超时 marker 自测。
- RC11 的 C11 协议投影、正确/错误发布程序及 DOT；原语 pure queue 与实际 pool benchmark 标签、slot bytes 和 producer 对照入口。

使用与边界见 [MPMC 说明](../mpmc-queue.md)。

## 性能与已保留失败

完整池与M2原frozen binary同日/同资源配置比较；primitive的mutex/mpmc用同一个当前control binary。只测开发代表点：单consumer/worker，producer1/4，global4096，Abort，2s warmup/10s measure，各5独立进程，median/IQR和worker/inline/拒绝/分组histogram/CPU秒保留。macOS unbound不能用于物理Linux正式结论，也不外推producer2/8。

首轮 `results/m3/performance-20261003/` 前3组有效；新增pure MPMC模式producer误路由mutex、consumer走MPMC，守恒检查拒绝，完整失败manifest/command/stderr保留。已修正并在Release mutex/MPMC、TSan、ASan四配置smoke验证；剩余测量新目录 `performance-routing-fixed-20261003/`，绝不把失败重跑抹成成功。有效旧组保留原binary/hash，新组保留修正后binary/hash；此变更只涉及此前失败的纯队列路由，pool路径未变。

### 代表点数据与五问（仅开发）

全部有效组各5独立进程，参数/日期/记录的环境相同；对照JSON：`results/m3/comparison-20261003.json`。primitive两个producer点都使用修正后的同一control binary；P1 mutex另在`primitive-control-matched-20261003`重测，旧有效数据仍保留。pool使用原M2 frozen binary对比相应M3 candidate，原语routing修正不改变pool路径；两版candidate各自hash与源码身份保留，不混称同一个binary。

| 路径 / producers | mutex median / IQR ops/s | MPMC median / IQR ops/s | median ratio |
|---|---:|---:|---:|
| primitive, P=1 | 2879623 / 49338 | 17245194 / 57389 | 5.989 |
| pool, P=1 | 1527911 / 100076 | 1824961 / 22032 | 1.194 |
| primitive, P=4 | 2941534 / 169630 | 9493785 / 202086 | 3.227 |
| pool, P=4 | 794720 / 32163 | 1210965 / 31569 | 1.524 |

1. **哪条路径与机制变快？** 受控原语免去enqueue/dequeue的mutex，新增position CAS和seq协议；实际池常态worker领取也免去队列mutex。数据支持这两个代表点的开发趋势，primitive ratio明显大于pool ratio，不把两者相减当独立耗时。
2. **成本转移？** Task* slot从8增为16 bytes，head/tail按构建cache配置对齐；CAS/seq cache coherence新成本替代普通锁保护访问。pool每次成功发布仍取通知mutex，gate/pending/submitted/wakes共享更新与Task分配/销毁未消失。未独立硬件采样，机制解释与实测事实分开。
3. **p99？** pool P1 mutex/MPMC median桶上界分别177.828/74.989 us，P4分别13335.214/93.057 us。它们是24.1%宽度直方图桶上界，不能据此关闭5%正式回归门槛。P4 mutex拒绝中位约2394308次/10336129尝试，MPMC约57次/12109821尝试；排队/供给/拒绝分布同时改变，不能把尾延迟下降全部归为CAS变快。原语没有Task latency，输出-1。
4. **是否只在单线程/均匀有效？** 已测P1/P4、固定单consumer/worker；pool所有inline比例0，未用CallerRuns扩展执行CPU。其余worker/producer数、开放到达率、工作粒度未作正式矩阵，不外推。
5. **偏斜扩展性？** primitive P4低于其P1，存在共享position/cache争用；这些是外部入口数据，M1/M3无local deque，不能拿它作worker scaling、单victim skew或NUMA结论。

结论：原语和池候选保留，**默认仍mutex**；不存在物理Linux/完整资源与负载矩阵证据，本机相对提升不是正式默认替换依据。所有失败/候选/原frozen归档不覆盖。


## 未关闭门禁

- Linux native/远端CI、固定物理机资源和正式性能矩阵仍缺；macOS与C11投影不能替代它们。
- M0/M1/M2 原门禁未由本轮关闭；watchdog打印近似atomic snapshot，portable版本没有所有线程堆栈，完整失败现场仍待平台实现。
- 新原语没有mutex，不代表整个池lock-free；claim暂停可能阻塞数据流，false只表示unavailable。
- 对照只提供受控queue路径与实际pool总体；没有单独硬件采样每个共享RMW，不作加性耗时分解或额外producer CPU伪装worker scaling。
- 保留默认mutex，不因本机某个有利负载直接切默认；M4–M7未开始。没有安装/升级工具、主仓库commit或push。
